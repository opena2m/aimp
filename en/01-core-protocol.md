# AIMP 01 — Core Protocol

**Status:** Draft · **Version:** 1.0.0-draft · **Normative**

This document defines the **domain-agnostic kernel** of AIMP. Every AIMP-conformant
gateway MUST implement every method in this document. Domain-specific behaviours live in
§02.

## 1. Transport & Encoding

- Requests and responses MUST be JSON (UTF-8, RFC 8259).
- The RECOMMENDED transport is HTTPS with RESTful semantics and JSON bodies.
- Long-running telemetry MAY additionally be offered over WebSocket, MQTT, or Server-Sent
  Events. If so, the gateway MUST still expose the polling endpoint in §6.4.
- All timestamps MUST be RFC 3339 with an explicit timezone offset, preferring UTC.
- All durations MUST be integer seconds unless a schema explicitly specifies otherwise.
- All monetary values MUST include an ISO 4217 currency code.

## 2. Protocol Roles

| Role | Description |
|---|---|
| **Client** | The AI agent (directly or via MCP) that issues AIMP calls. |
| **Gateway** | The AIMP server. Holds policy, budget state, the ledger, the job registry, and adapter routing. |
| **Adapter** | The edge component that speaks to the physical machine. Transparent to the client. |

All normative statements about AIMP endpoints apply to the **Gateway**.

## 3. Common Request Envelope

Every AIMP request body MUST be wrapped in the common envelope:

```json
{
  "aimp_version": "1.0",
  "job_id": "01J8K9Z4X0R3S7Q6V2N4T8W1YM",
  "timestamp": "2026-04-24T05:19:36Z",
  "idempotency_key": "client-generated-opaque-string",
  "metadata": {
    "creator": "agent://acme-factory/design-bot-7",
    "trace_id": "opentelemetry-trace-id",
    "tags": {"project": "poster-run-17"}
  }
}
```

Beyond these envelope fields, each method defines its own body fields.

- `aimp_version` — MUST match the spec major.minor implemented by the gateway.
- `job_id` — a ULID or UUIDv7 generated by the **client**. Gateway-visible identifier.
- `idempotency_key` — OPTIONAL but RECOMMENDED. A gateway receiving two requests with the
  same `idempotency_key` within its retention window MUST return the original response
  without performing the action again.
- `metadata` — free-form; gateways MUST echo `trace_id` if present in telemetry and
  webhooks.

## 4. Core State Machine

Every job (`job_id`) proceeds through a subset of the following states, in order. States
MUST NOT be skipped except by transition to `ABORTED` or `FAILED`, which is always legal.

```
   PENDING
       │
       ▼
   QUOTED ─────────────────────┐
       │                       │
       ▼                       │
   LOCKED                      │
       │                       │
       ▼                       │
   EXECUTING ◀──┐              │
       │        │              │
       ▼        │              │
   AUDITING ────┘   (resume)   │
       │                       │
       ▼                       │
   FULFILLING                  │
       │                       │
       ▼                       ▼
   COMPLETED              ABORTED / FAILED
```

| State | Meaning | Terminal? |
|---|---|---|
| `PENDING` | Gateway accepted the envelope; validation in progress. | no |
| `QUOTED` | A valid quote has been issued with a price and a `valid_until`. | no |
| `LOCKED` | The client confirmed and resources are reserved; execution has not yet begun. | no |
| `EXECUTING` | The physical machine is actively working. `progress` is meaningful. | no |
| `AUDITING` | Execution paused for AI or human review of audit media. | no |
| `FULFILLING` | Execution completed; logistics (packaging, shipping) in progress. | no |
| `COMPLETED` | Successful terminal state. | **yes** |
| `ABORTED` | Terminal — the client or a policy rule halted the job. Partial costs MAY apply. | **yes** |
| `FAILED` | Terminal — the physical process or adapter failed. An `error_code` MUST be set. | **yes** |

Gateways MUST reject client-initiated state transitions that are not in this table. Only
`ABORT` (§6.5) and resume-from-`AUDITING` are client-initiated; all others are gateway-
driven.

## 5. Identity, Auth, and Trust

- Clients MUST authenticate on every request. The RECOMMENDED scheme is OAuth 2.1 bearer
  tokens with short-lived credentials, scoped per-device or per-domain.
- Gateways MUST enforce a **policy** that binds each token to: (a) allowed domains,
  (b) allowed devices, (c) a budget ceiling.
- Human-in-the-loop approvals (§04) MUST be signed by a separate principal distinct from
  the calling agent.
- Gateways MUST log every state transition and every policy decision to an append-only
  audit log.

## 6. Core Methods

The Core defines exactly **five** verbs. Any additional endpoint is domain extension
(§02) or gateway convenience.

### 6.1 `discover` — capability handshake

**Purpose:** Let the client learn what the gateway can do before committing to any plan.

```
POST /v1/discover
Content-Type: application/json
Authorization: Bearer <token>

Request body:
{
  "envelope": { ...common envelope... },
  "device_filter": {
    "domains": ["manufacturing.additive.*"],      // optional glob list
    "device_ids": ["printer-01"]                  // optional
  }
}
```

**Response:**

```json
{
  "job_id": "<same as request>",
  "aimp_version": "1.0",
  "conformance_level": "L3",
  "devices": [
    {
      "device_id": "printer-01",
      "device_class": "PRINTER_3D",
      "domains": ["manufacturing.additive.fdm.v1"],
      "state": "IDLE",
      "consumables": [
        {"name": "PLA_white", "quantity": 412.5, "unit": "g"},
        {"name": "PETG_black", "quantity": 0.0, "unit": "g"}
      ],
      "build_volume_mm": {"x": 220, "y": 220, "z": 250},
      "audit_channels": ["camera.top", "sensor.extruder_temp"]
    }
  ]
}
```

Gateways SHOULD cache `discover` responses for short periods (seconds, not minutes);
consumable state changes rapidly.

### 6.2 `quote` — price a proposed job

**Purpose:** Obtain a firm, time-bound price quote. This MUST NOT start any physical work.

```
POST /v1/quote

Request body:
{
  "envelope": { ...common envelope... },
  "device_id": "printer-01",
  "domain": "manufacturing.additive.fdm.v1",
  "asset": {
    "type": "3D_MODEL",
    "format": "model/gcode",
    "url": "https://assets.example.com/gear.gcode",
    "hash_sha256": "e3b0c44..."
  },
  "payload": { ...domain-specific parameters... },
  "logistics": { ...optional recipient info... },
  "budget_limit": {"amount": 25.00, "currency": "USD"}
}
```

**Response:**

```json
{
  "job_id": "<same as request>",
  "state": "QUOTED",
  "quote_id": "quote_01J8...",
  "estimated_cost": {
    "currency": "USD",
    "amount": 18.20,
    "breakdown": {
      "material": 6.40,
      "machine_time": 4.80,
      "logistics": 7.00,
      "service_fee": 0.00
    }
  },
  "resource_consumption": {
    "material": [{"name": "PLA_white", "quantity": 38.2, "unit": "g"}],
    "machine_time_seconds": 4380,
    "energy_kwh": 0.42
  },
  "valid_until": "2026-04-24T06:19:36Z"
}
```

If the estimate exceeds `budget_limit`, the gateway MUST still return a `QUOTED` response
but set `exceeds_budget: true`. The client is responsible for declining.

### 6.3 `execute` — confirm a quote and start work

**Purpose:** Commit the quote, lock resources, and begin physical execution.

```
POST /v1/execute

Request body:
{
  "envelope": { ...common envelope... },
  "quote_id": "quote_01J8...",
  "approval_token": "<required if policy demands human-in-the-loop>",
  "audit_requirements": {
    "snapshot_interval_seconds": 180,
    "sensors": ["extruder_temp", "chamber_temp"],
    "ai_vision_checks": ["detect_spaghetti_failure"],
    "pause_for_human_at": ["mid_build_50_percent"]
  }
}
```

**Response (immediate, typically `202 Accepted`):**

```json
{
  "job_id": "<same as request>",
  "state": "LOCKED",
  "transition_eta": "2026-04-24T05:19:40Z"
}
```

The gateway MUST then transition through the state machine (§4) asynchronously and push
updates via webhook, stream, or polling.

The client MUST NOT assume any physical work has begun until `state == "EXECUTING"`.

### 6.4 `telemetry` — observe

**Purpose:** Retrieve the current state and any multimodal audit data.

```
GET /v1/jobs/{job_id}/telemetry
GET /v1/jobs/{job_id}/telemetry?since=<rfc3339>
```

**Response:**

```json
{
  "job_id": "01J8K9...",
  "state": "EXECUTING",
  "progress": 0.47,
  "updated_at": "2026-04-24T05:41:02Z",
  "sensor_readings": [
    {"channel": "extruder_temp", "value": 210.2, "unit": "degC", "at": "2026-04-24T05:41:00Z"},
    {"channel": "chamber_temp",  "value": 41.1,  "unit": "degC", "at": "2026-04-24T05:41:00Z"}
  ],
  "media": [
    {
      "channel": "camera.top",
      "kind": "image/jpeg",
      "url": "https://gateway.example.com/media/job-01J8.../top-00012.jpg",
      "captured_at": "2026-04-24T05:40:59Z",
      "expires_at": "2026-04-25T05:40:59Z"
    }
  ],
  "human_action_required": null
}
```

Media URLs MUST be pre-signed and short-lived. Clients MUST NOT rely on them beyond
`expires_at`.

When the state is `AUDITING`, the response MUST include `human_action_required` with the
fields needed to resume (see §5 of the audit document, `05-audit-and-telemetry.md`).

### 6.5 `abort` — stop immediately

**Purpose:** Physical emergency stop. Highest priority.

```
POST /v1/jobs/{job_id}/abort

Request body:
{
  "envelope": { ...common envelope... },
  "reason": "vision_check_failed_spaghetti",
  "recovery_mode": "safe_home"      // "safe_home" | "hard_stop" | "freeze"
}
```

**Response:**

```json
{
  "job_id": "01J8K9...",
  "state": "ABORTED",
  "final_cost": {"currency": "USD", "amount": 2.85, "breakdown": {...}},
  "partial_outputs": [
    {"kind": "scrap", "description": "failed print, approx 12 g PLA", "disposal": "user-collect"}
  ]
}
```

Adapters MUST execute the abort with the shortest feasible latency. A `hard_stop` cuts
motion and heat immediately; a `safe_home` parks the tool safely; a `freeze` leaves state
untouched pending inspection. Gateways MUST validate that the requested mode is supported
by the device; if not, they MUST fall back to the most conservative supported mode and
report this in the response.

## 7. Webhook Notifications

A gateway offering webhook delivery MUST, for each subscribed job, deliver a JSON payload
on every state transition:

```json
{
  "event": "state_transition",
  "aimp_version": "1.0",
  "job_id": "01J8K9...",
  "from": "EXECUTING",
  "to":   "AUDITING",
  "at":   "2026-04-24T05:49:18Z",
  "telemetry_summary": { ...subset of §6.4 response... },
  "signature": "hmac-sha256=..."
}
```

Webhooks MUST be signed with HMAC-SHA256 over the canonical body using a per-subscription
secret. Receivers MUST reject unsigned or mis-signed webhooks. Retries SHOULD follow
exponential backoff up to 24 hours.

## 8. Idempotency

- Re-POSTing the same `idempotency_key` to `quote` or `execute` MUST return the original
  result unchanged for the retention window (RECOMMENDED: 24 hours).
- `abort` is idempotent by nature: repeated aborts on a terminal job MUST succeed silently.
- `discover` and `telemetry` are naturally idempotent.

## 9. Rate Limits

Gateways MUST expose per-token rate limits via `X-RateLimit-*` headers. Clients MUST
respect `Retry-After`. Default RECOMMENDED limits:

| Method | Per minute | Per hour |
|---|---|---|
| `discover`, `telemetry` | 120 | 3000 |
| `quote` | 30 | 300 |
| `execute` | 10 | 120 |
| `abort` | unlimited | unlimited |

Aborts are never rate-limited: physical safety MUST always win.

## 10. Minimal Conformance Test

An implementation claims **L1 Core** conformance if, for a reference stub device, it:

1. Responds to `/discover` with at least one device entry.
2. Accepts a `/quote` call and returns a `QUOTED` state with `quote_id` and
   `valid_until` ≥ 30 seconds in the future.
3. Accepts a matching `/execute` call and returns `LOCKED` within 500 ms.
4. Reaches `COMPLETED` via `/telemetry` polling within a bounded time.
5. Supports `/abort` at any non-terminal state.

Test vectors are published under `schemas/` and in the companion conformance suite.
