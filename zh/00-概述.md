# AIMP 00 — 概述与架构

**状态:** 草案 · **版本:** 1.0.0-draft · **读者:** 全体

## 1. 摘要

**AIMP（AI-to-Machine Protocol，AI 到机器协议）** 是一套标准化协议集合，使 AI 系统能够
通过异构物理设备 —— 包括打印机、3D 打印机、数控机床、机械臂、实验室仪器、智能厨电、无人
机等 —— 产出真实、可触及的产品；并在能力发现、成本询价、任务执行、多模态审核和物流履约
各环节，保持统一的语义约定。

AIMP **有意** 不重新发明传输协议。它是一层语义协议，旨在架设在既有 AI 工具协议（MCP、A2A、
OpenAI 兼容函数调用）与既有传输协议（HTTP/REST、MQTT、WebSocket）之上。它唯一的贡献是：
在 **AI 意图** 与 **物理执行** 之间，建立一份有纪律的合约。

## 2. 问题陈述

现代大语言模型能够生成图像、3D 模型、G-code、CAD 图纸、电路版图、化学配方和动作计划。
把这些数字成果落地到现实中，目前只有两条路：

- 为每一台设备、每一家厂商写专用胶水代码，没有任何关于成本、安全、可观测性的共享语义；
- 使用单一厂商的围墙花园（按需云打印、专有工厂），牺牲互操作性。

缺失的两个基本抽象是：

1. **统一的生命周期契约** —— 让 AI Agent 操作 3D 打印机的方式，与操作移液机器人或激光
   切割机的方式完全一致。
2. **安全护栏** —— 防止自主 Agent 意外烧钱、损毁设备或伤人。物理动作是不可逆的；提示词
   注入和模型幻觉在物理世界里代价惨重。

AIMP 同时解决这两点。

## 3. 设计原则

### 3.1 微内核 + 领域插件

一套严格领域无关的 **核心协议**（§01），负责所有物理任务共有的关注点 —— 能力发现、询价、
执行握手、遥测、紧急中止。所有领域特定语义（喷嘴温度、关节角度、移液体积、切削进给速度）
都放入 **领域 Schema**（§02），按层级命名空间组织，例如
`manufacturing.additive.fdm.v1` 或 `kinematics.robotic_arm.v2`。

这是 POSIX、OpenGL、Web 技术栈能够长盛不衰的同一种分割方式：稳定的内核 + 版本化的扩展。

### 3.2 默认零信任

每一次物理动作都要走 **询价 → 锁定 → 执行 → 审核 → 结算** 的流水线。AI 绝不能跳过询价
直接执行。网关会追踪：

- 货币成本
- 耗材消耗（耗材丝克数、试剂毫升数、电量、纸张、墨水……）
- 实际墙钟时间
- 风险等级（是否不可逆？是否涉及人？是否涉及危化品？）

预算由网关强制执行，而非依赖 Agent 的"荣誉系统"。Human-in-the-Loop（HITL）检查点是协议
的一等状态，不是事后补丁。

### 3.3 异步可观测

物理时间比计算时间慢几个数量级。AIMP 全链路异步：Agent 提交意图，网关返回 `job_id`；
Agent 随后通过轮询 `/telemetry` 或订阅 webhook 获取状态变化。每个任务都暴露：

- 归一化的 `progress` 进度（`[0.0, 1.0]`）
- 来自核心状态机的归一化 `state`
- 可选的多模态遥测：摄像头帧、传感器读数、日志

### 3.4 嵌入，而不是重造

AIMP **不** 与 MCP、A2A、OpenAI tools、LangGraph 竞争。相反：

- 在通过 **MCP** 调用 Agent 看来，AIMP 网关只是又一个 MCP Server，提供 `aimp.quote`、
  `aimp.execute`、`aimp.telemetry` 等工具。
- 在 **A2A**（Agent 间协作）拓扑中，AIMP 是专职 "执行 Agent（Executor Agent）" **唯一**
  被允许触及的接口。设计、审计、财务、调度 Agent 之间用 A2A 讨论；所有触达物理世界的动作
  都通过 AIMP 这个瓶颈。
- AIMP 请求可以走任何支持双向 JSON 的传输。

### 3.5 闭环感知

协议不是"只写"的。网关 **必须** 有能力回传多模态遥测：摄像头快照、传感器时间序列、过程日志。
这使得以下操作成为可能：

- AI 侧的视觉校验（"成品是否与 CAD 模型一致？"）
- 在缺陷早期中止任务（FDM 打印中经典的 "炒面（spaghetti failure）" 现象）
- 根据历史数据自适应调整后续任务参数

## 4. 架构

AIMP 定义了三个逻辑组件，以及更大栈中的四个层次。

### 4.1 组件

```
┌──────────────────────┐       ┌──────────────────────┐       ┌──────────────────────┐
│  AI 客户端 / Agent    │──────▶│   AIMP 网关           │──────▶│  硬件适配器          │
│  （大模型 + 工具）    │◀──────│  （核心协议）         │◀──────│ （ROS/G-code/Modbus）│
│                      │       │                      │       │                      │
│  - 意图              │       │  - 路由              │       │  - 将 AIMP JSON       │
│  - 预算策略          │       │  - 鉴权与策略        │       │    翻译为机器指令    │
│  - 视觉审核          │       │  - 询价 / 锁定 / 执行 │       │  - 传感器回读        │
│                      │       │  - 遥测中继          │       │                      │
└──────────────────────┘       └──────────────────────┘       └──────────────────────┘
         ▲                               │                               │
         │                               ▼                               ▼
         │                        ┌──────────────┐                ┌────────────────┐
         │                        │  账本 &      │                │  物理机器      │
         └────── webhooks ────────│  审计日志    │                │                │
                                  └──────────────┘                └────────────────┘
```

**AI 客户端 / Agent。** 大脑。持有用户意图、预算和用于审核的视觉模型。通过 MCP 或函数调用
绑定调用 AIMP 工具。

**AIMP 网关。** 脊髓。一个有状态的中间件服务：鉴权、策略执行、发起询价、锁定资源、派发执行、
中继遥测、写入审计日志。网关是 **唯一** 真正花钱的位置。

**硬件适配器。** 神经末梢与肌肉。部署在设备处或设备内部。把验证过的 AIMP payload 翻译成
设备原生语言（G-code、PostScript、ROS action、OPC-UA、Modbus，或厂商专用 REST API），
并回报传感器遥测。

### 4.2 栈分层

| 层 | 名称 | 关注点 | 典型协议 |
|---|---|---|---|
| L7 | 意图层 | 自然语言目标 | 人类 / LLM 提示 |
| L6 | 协作层 | 多 Agent 规划与复核 | A2A、AutoGen、Swarm |
| L5 | 工具接入层 | 函数调用的打包与路由 | **MCP**、OpenAI tools |
| L4 | 物理编排层 | 询价 / 锁定 / 执行 / 审核 | **AIMP 核心（§01）** |
| L3 | 领域动作层 | 喷嘴温度、关节角度、体积 | **AIMP 领域 Schema（§02）** |
| L2 | 驱动层 | 脉冲与字节 | ROS、G-code、Modbus、OPC-UA |
| L1 | 物理层 | 原子与光子 | — |

AIMP 严格占据 L4 + L3。它是 **抽象层**，不与任何其他层竞争。

## 5. 与周边标准的关系

- **MCP（Model Context Protocol）。** AIMP 网关 **应当** 以 MCP Server 的形式暴露自己，
  让任何支持 MCP 的 Agent 无需手写代码即可发现并使用。详见 §03。
- **OpenAI / Anthropic / Gemini 函数调用。** AIMP 核心方法可一一映射为函数工具。核心的
  JSON-Schema 导出发布在 `schemas/core/`。
- **A2A / Agent 间协议。** AIMP 在任何 A2A 拓扑中扮演"物理执行者"角色。详见 §03。
- **工业控制栈（ROS、OPC-UA、MTConnect）。** AIMP 位于这些协议之 **上**。硬件适配器负责
  桥接。
- **按需云打印 API（Printful、Printify、阿里云制造、等）。** 这些只是 AIMP 网关的
  **一个特化实例**，专注于 2D 打印领域。

## 6. 版本管理与合规等级

AIMP 版本沿用针对整份文档集的语义化版本号。实现方可声明以下三个合规等级之一：

- **L1 核心。** 实现 §01 的五个核心方法。无音像审核，无预算强制。最低要求。
- **L2 标准。** 在 L1 基础上，实现 询价-锁定-执行-结算 的成本闭环，并支持基础遥测
  （进度 + 状态）。
- **L3 完整。** 在 L2 基础上，支持多模态审核（摄像头/传感器流）、Human-in-the-Loop
  检查点，并至少支持一个发布过的领域 Schema。

网关通过 `GET /capabilities` 声明自身等级（§01.4）。

## 7. 不在范围内

AIMP **不** 规定：

- 必须使用哪种传输协议（推荐 HTTPS/REST；允许 MQTT/WebSocket）。
- 身份与密钥管理方式（由实现自主选择 OAuth2 / mTLS / 签名 Token 等）。
- 任何具体耗材的价格（网关自声明）。
- 任何 Agent 的内部规划算法（那是 Agent 自己的事情）。
