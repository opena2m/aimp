# AIMP 06 — 错误码

**状态：** 草案 · **版本：** 1.0.0-draft · **规范性**

AIMP 定义一组封闭的标准错误码。网关与适配器在通过响应、遥测或 Webhook 暴露故障时，
**必须（MUST）**使用这些错误码。厂商专属错误码仅允许以 `VENDOR_` 为前缀，
且**必须（MUST）**同时映射到最接近的标准错误码。

## 1. 错误信封

所有错误响应**必须（MUST）**遵循以下结构：

```json
{
  "error": {
    "code": "ERR_BUDGET_EXCEEDED",
    "message": "Quoted amount 28.40 USD exceeds remaining daily budget 14.60 USD.",
    "category": "policy",
    "retryable": false,
    "retry_after_seconds": null,
    "details": {
      "budget_ceiling": 200.00,
      "budget_consumed": 185.40,
      "quote_amount": 28.40,
      "currency": "USD"
    },
    "remediation": "Reduce job scope, wait for budget reset, or request ceiling increase.",
    "trace_id": "0f7a..."
  }
}
```

字段说明：

- **`code`** —— 来自下文的枚举列表，**必须（MUST）**为保留值之一。
- **`message`** —— 人类可读，单句表述，对代理安全（不含机密信息）。
- **`category`** —— 取值范围：`validation`、`auth`、`policy`、`resource`、
  `hardware`、`asset`、`network`、`safety`、`vendor`、`internal`。
- **`retryable`** —— 布尔值；指示相同请求在稍后是否可能成功。
- **`retry_after_seconds`** —— 可选；在已知重试窗口时存在。
- **`details`** —— 自由格式、领域相关的诊断信息。
- **`remediation`** —— 面向调用方的可操作下一步建议。
- **`trace_id`** —— 与日志关联的追踪标识。

## 2. 标准错误码

### 2.1 校验类（`validation`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_INVALID_ENVELOPE` | 400 | 通用信封格式错误或缺少必填字段。 |
| `ERR_INVALID_DOMAIN` | 400 | `domain` 命名空间不被网关识别。 |
| `ERR_INVALID_PAYLOAD` | 400 | `payload` 未通过领域 Schema 校验。 |
| `ERR_VERSION_UNSUPPORTED` | 400 | `aimp_version` 与网关不兼容。 |
| `ERR_DUPLICATE_IDEMPOTENCY_CONFLICT` | 409 | 相同 `idempotency_key` 被用于不同请求体。 |

### 2.2 认证与授权类（`auth`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_UNAUTHENTICATED` | 401 | 缺失或无效的凭证。 |
| `ERR_TOKEN_EXPIRED` | 401 | 访问令牌已过 `exp`。 |
| `ERR_FORBIDDEN_DOMAIN` | 403 | 令牌作用域不包含所请求 `domain`。 |
| `ERR_FORBIDDEN_DEVICE` | 403 | 令牌作用域不包含所请求 `device_id`。 |
| `ERR_APPROVAL_REQUIRED` | 403 | 策略要求该操作附带人工 `approval_token`。 |
| `ERR_APPROVAL_INVALID` | 403 | `approval_token` 签名无效、过期或作用域不符。 |

### 2.3 策略类（`policy`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_BUDGET_EXCEEDED` | 402 | 执行该报价将超出预算上限。 |
| `ERR_RATE_LIMITED` | 429 | 该主体请求过频。**必须（MUST）**返回 `retry_after_seconds`。 |
| `ERR_RISK_TIER_BLOCKED` | 403 | 当前环境已禁用该领域对应的风险等级。 |
| `ERR_QUOTE_EXPIRED` | 410 | `quote_id` 已超过 `valid_until`。 |
| `ERR_QUOTE_UNKNOWN` | 404 | `quote_id` 不存在。 |

### 2.4 资源类（`resource`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_DEVICE_NOT_FOUND` | 404 | `device_id` 不存在。 |
| `ERR_DEVICE_BUSY` | 409 | 设备正在服务其他作业，请稍后重试。 |
| `ERR_DEVICE_OFFLINE` | 503 | 适配器不可达。 |
| `ERR_INSUFFICIENT_CONSUMABLE` | 409 | 所需材料或耗材数量不足。 |
| `ERR_UNSUPPORTED_CAPABILITY` | 422 | 请求参数组合超出设备能力（如体积过大）。 |

### 2.5 硬件类（`hardware`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_HARDWARE_FAULT` | 500 | 适配器报告设备侧故障。 |
| `ERR_HARDWARE_STALL` | 500 | 运动失步 / 机械卡阻。 |
| `ERR_HARDWARE_OVERTEMP` | 500 | 温度超出限值。 |
| `ERR_HARDWARE_EMERGENCY_STOP` | 500 | 物理急停被触发。 |
| `ERR_CALIBRATION_REQUIRED` | 503 | 设备需要校准 / 换刀 / 调平。 |

### 2.6 资产类（`asset`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_ASSET_UNREACHABLE` | 502 | 无法从 `asset.url` 获取资产。 |
| `ERR_ASSET_HASH_MISMATCH` | 422 | 下载字节与 `hash_sha256` 不符。 |
| `ERR_ASSET_FORMAT_REJECTED` | 415 | 格式不在领域 Schema 的可接受清单内。 |
| `ERR_ASSET_TOO_LARGE` | 413 | 资产超出网关或设备上限。 |
| `ERR_ASSET_CONTENT_POLICY` | 451 | 资产违反内容或安全策略。 |

### 2.7 网络类（`network`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_UPSTREAM_TIMEOUT` | 504 | 上游依赖（厂商 API、存储）未在规定时间内响应。 |
| `ERR_WEBHOOK_DELIVERY_FAILED` | — | 仅作遥测出现；客户端未 ACK Webhook。 |

### 2.8 安全类（`safety`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_UNSAFE_PARAMETER` | 422 | 参数将超出设备声明的安全包络。 |
| `ERR_COLLISION_RISK` | 422 | 运动规划与禁入区或其他活跃作业相交。 |
| `ERR_INTERLOCK_OPEN` | 503 | 安全互锁（门、光幕）未闭合。 |
| `ERR_VISION_AUDIT_FAILED` | — | 视觉审核裁决为 `failure`，与 `ABORTED` 状态同时出现。 |

### 2.9 厂商类（`vendor`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `VENDOR_<名称>_<编码>` | 不定 | 厂商专属错误。**必须（MUST）**在 `details` 中附带 `standard_equivalent`。 |

### 2.10 内部类（`internal`）

| 代码 | HTTP | 含义 |
|---|---|---|
| `ERR_INTERNAL` | 500 | 网关缺陷；允许带退避重试。 |
| `ERR_SERVICE_DEGRADED` | 503 | 网关运行于降级模式，部分功能可用。 |

## 3. 通过遥测上报错误

以 `FAILED` 状态结束的作业**必须（MUST）**经由遥测暴露其错误：

```json
{
  "job_id": "01J8K9...",
  "state": "FAILED",
  "progress": 0.32,
  "updated_at": "2026-04-24T05:59:00Z",
  "error": {
    "code": "ERR_HARDWARE_OVERTEMP",
    "category": "hardware",
    "retryable": false,
    "details": {"channel": "extruder_temp", "value": 285.0, "limit": 260.0}
  }
}
```

因安全原因以 `ABORTED` 状态结束的作业**必须（MUST）**携带适用的安全类错误码，
例如 `ERR_VISION_AUDIT_FAILED` 或 `ERR_INTERLOCK_OPEN`。

## 4. 代理的错误恢复指南

一个合规的 AI 客户端**应当（SHOULD）**实现以下恢复策略：

| 类别 | 建议行为 |
|---|---|
| `validation` | 不重试；修正请求。 |
| `auth` | 刷新令牌；仍失败则上报操作人。 |
| `policy` | 若 `ERR_BUDGET_EXCEEDED`，不重试；请求审批或削减范围。若 `ERR_RATE_LIMITED`，遵循 `retry_after_seconds`。 |
| `resource` | 对 `ERR_DEVICE_BUSY`，带抖动重试；对 `ERR_INSUFFICIENT_CONSUMABLE`，通知操作人。 |
| `hardware` | 上报人工；代理**不应**对同一故障自动重试超过一次。 |
| `asset` | 重新生成或重新拉取资产；重算哈希；重试。 |
| `network` | 带抖动的指数退避，设定合理上限。 |
| `safety` | **永不**自动重试；必须显式人工介入。 |
| `internal` | 指数退避。 |

## 5. 按领域扩展

领域 Schema **可以（MAY）**在命名空间前缀下定义额外的领域专属错误码，
例如在 `manufacturing.additive.fdm.v1` 下注册 `ERR_FDM_NOZZLE_CLOG`。
这类错误码**必须（MUST）**同时映射到上文标准类别之一，以供通用处理。

## 6. 本地化

错误 `message` 文本**应当（SHOULD）**根据请求的 `Accept-Language` 头进行本地化。
`code` 字段**必须（MUST）**始终保持其 ASCII 规范形式，不随语言改变。
