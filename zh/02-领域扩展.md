# AIMP 02 — 领域扩展

**状态:** 草案 · **版本:** 1.0.0-draft · **规范性**

AIMP 核心（§01）对喷嘴、关节、移液头、激光头一无所知。所有领域语义都位于 **领域 Schema**
中，独立于核心进行发现与版本管理。本章规定如何编写、注册和演进这些 Schema。

## 1. 命名空间约定

每个领域由一个"反向点分"的小写命名空间、外加显式版本后缀标识：

```
<category>.<subcategory>[.<specialization>...].v<major>
```

示例：

```
manufacturing.additive.fdm.v1           FDM（熔融沉积）3D 打印
manufacturing.additive.slm.v1           选择性激光熔化
manufacturing.subtractive.cnc_mill.v1   三轴 CNC 铣削
manufacturing.print.2d.v1               喷墨/激光二维打印
kinematics.robotic_arm.v1               六轴工业机械臂
kinematics.mobile_robot.v1              AGV / 轮式机器人
kinematics.drone.v1                     无人机平台
fluidics.pipette.v2                     实验室液体处理
fluidics.mixing.v1                      生物反应器 / 化学搅拌
thermodynamics.cooking.v1               智能厨电
thermodynamics.reaction.v1              化学反应釜
optics.imaging.v1                       摄像 / 显微成像
sensing.spectroscopy.v1                 光谱仪
logistics.shipping.v1                   物流揽件
```

### 1.1 类别（规范性，顶层保留）

协议保留如下顶层类别名：

```
manufacturing   additive, subtractive, forming, assembly, print
kinematics      arms, mobile, aerial, underwater
fluidics        pipette, pumping, mixing
thermodynamics  heating, cooling, reaction, cooking
optics          imaging, projection
sensing         spectroscopy, metrology, weight, gas
logistics       shipping, storage, sortation
```

新增顶层类别 **必须** 经由注册流程（§4）。子层级开放自由扩展。

### 1.2 版本规则

- `.v<N>` 后缀表示 **主版本**。任何破坏性变更都要提升。
- 向后兼容的小变更（新增可选字段）**应当** 沿用现有主版本，通过 Schema 自身的 `$id` 与
  `schemaVersion` 字段标示。
- 网关在 `discover` 中 **必须** 列出所有支持的 `(命名空间, 版本)` 对。
- 客户端在 `execute` 时 **必须** 明确指定版本。可以在 `quote` 阶段列出多个候选版本用于
  协商，例如 `["manufacturing.additive.fdm.v1", "manufacturing.additive.fdm.v2"]`。

## 2. 领域 Schema 的构成

领域 Schema 是一份 JSON Schema 2020-12 文档，定义 `quote` 或 `execute` 请求中
`payload` 字段的合法结构（§01.6）。它 **应当** 同时声明可选的 `audit_requirements`
扩展和耗材类型。

每份领域 Schema 至少 **必须** 提供：

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://aimp.dev/schemas/manufacturing.additive.fdm.v1.json",
  "title": "FDM 3D 打印 Payload",
  "aimp_domain": "manufacturing.additive.fdm.v1",
  "type": "object",
  "required": ["asset", "material_requirement", "parameters"],
  "properties": {
    "asset": {
      "type": "object",
      "required": ["url", "format"],
      "properties": {
        "url":    {"type": "string", "format": "uri"},
        "format": {"type": "string", "enum": ["model/gcode", "model/stl", "model/3mf"]},
        "hash_sha256": {"type": "string"}
      }
    },
    "material_requirement": {
      "type": "string",
      "enum": ["PLA", "PETG", "ABS", "TPU", "Nylon"]
    },
    "parameters": {
      "type": "object",
      "properties": {
        "nozzle_temp_celsius":   {"type": "number", "minimum": 150, "maximum": 300},
        "bed_temp_celsius":      {"type": "number", "minimum": 0,   "maximum": 120},
        "infill_percent":        {"type": "number", "minimum": 0,   "maximum": 100},
        "layer_height_mm":       {"type": "number", "minimum": 0.05,"maximum": 0.8}
      }
    }
  }
}
```

参考领域的机器可读版本放在 `schemas/domains/` 目录下。

## 3. 所有领域共通的字段

任何发布的领域 Schema 除自身字段之外，**必须** 同时包含以下字段（适用时）：

- **`asset`** *(适用时)* —— 指向数字输入的引用（G-code、CAD、图像、配方、轨迹文件）。
  Schema **必须** 通过 MIME 或显式 `enum` 列出可接受的格式。
- **`parameters`** —— AI 允许调节的"旋钮"。**必须** 用 `minimum`/`maximum`/`enum`/
  `pattern` 等机制表达可校验的边界。
- **`material_requirement` / `consumable_requirements`** *(适用时)* —— 机器将消耗
  的物料。网关据此计算 `quote` 中的 `resource_consumption`。

## 4. 领域注册表

为避免生态碎片化，合规的 AIMP 网关 **应当** 通过注册表解析未知领域：

```
GET https://registry.aimp.dev/domains/<namespace>/<version>
```

注册表返回权威的 JSON Schema 文档。网关 **可以** 缓存。新领域发布方 **必须** 同时提交：

1. JSON Schema 文档本身。
2. 简短散文说明（不超过 2 页）。
3. 至少一个完整的端到端请求示例及预期响应。
4. 风险等级声明（§04.4）。

在隔离网络中运行的网关无法访问在线注册表，它们 **必须** 随附本地支持的全部 Schema。

## 5. 扩展规则

- 领域 Schema **不得** 重命名或改变核心信封（§01.3）中任何字段的含义。
- 领域 Schema **可以** 定义 **自定义审计通道**（例如光谱领域增加 `audit_channels:
  ["spectrometer.raw"]`）。网关 **必须** 在 `discover` 中声明。
- 领域 Schema **可以** 通过 `required_sensors` 要求 **额外的传感器读数**。网关 **必须**
  拒绝针对不暴露这些传感器的设备的 `execute` 请求。
- 领域 Schema **应当** 自我分类为某一 **风险等级**（§04.4）：`routine`（常规）、
  `restricted`（受限）、`hazardous`（危险）。风险等级决定默认的 HITL 策略。

## 6. 多步操作

某些领域（机器人、流体）本质上是原子动作的序列。**推荐** 使用 `operations` 数组：

```json
"payload": {
  "operations": [
    {"step": 1, "type": "MOVE_TO_COORDINATE",
     "coordinates": {"x": 105.2, "y": 45.0, "z": 10.5}, "precision_mm": 0.1},
    {"step": 2, "type": "ASPIRATE_FLUID", "volume_microliters": 50},
    {"step": 3, "type": "MOVE_TO_COORDINATE",
     "coordinates": {"x": 140.0, "y": 45.0, "z": 10.5}, "precision_mm": 0.1},
    {"step": 4, "type": "DISPENSE_FLUID", "volume_microliters": 50}
  ]
}
```

每种 `type` 的结构由领域 Schema 的 `$defs` 约束。

多步操作 **可以** 通过在单步上附 `audit_after: true` 来规定 **逐步审核闸门**。

## 7. 领域覆盖范例

下表展示完全不同的物理场景在同一内核下的落地方式：

| 场景 | 领域 | 关键 payload 字段 | 典型审计通道 |
|---|---|---|---|
| 二维海报打印 | `manufacturing.print.2d.v1` | `paper_size`、`color_mode`、`dpi` | `camera.output_tray` |
| FDM 3D 打印 | `manufacturing.additive.fdm.v1` | `nozzle_temp`、`infill_percent` | `camera.top`、`extruder_temp` |
| CNC 铣削 | `manufacturing.subtractive.cnc_mill.v1` | `tool_id`、`feed_rate`、`spindle_rpm` | `vibration`、`spindle_load` |
| 取放机械臂 | `kinematics.robotic_arm.v1` | `end_effector_pose`、`grip_force_N` | `camera.workcell`、`force_torque` |
| 实验室移液 | `fluidics.pipette.v2` | `source_well`、`dest_well`、`volume_ul` | `liquid_level`、`camera.rack` |
| 低温慢煮 | `thermodynamics.cooking.v1` | `target_temp`、`duration` | `core_temp`、`camera.bath` |
| 包裹揽件 | `logistics.shipping.v1` | `carrier`、`service_level`、`recipient` | `waybill_barcode_scan` |

## 8. 新领域撰写清单

在向注册表发布新的领域 Schema 之前：

- [ ] 命名空间为反向点分、小写、带版本后缀。
- [ ] JSON Schema 通过 2020-12 草案校验。
- [ ] 所有物理上有意义的数值参数都具备 `minimum` 与 `maximum`。
- [ ] 所有枚举都是封闭的；开放字符串仅保留给真正不透明的标识符。
- [ ] 如依赖传感器反馈，已声明 `required_sensors`。
- [ ] 已声明风险等级。
- [ ] 附带至少一个通过校验的参考请求示例。
- [ ] 存在参考或厂商实现的适配器。
