# AIMP 07 — 参考场景

**状态：** 草案 · **版本：** 1.0.0-draft · **资料性**

本章通过四个具体的端到端场景演示完整协议的运作。所有 JSON 片段经简化以便阅读；
完整的请求 / 响应体见本规范同目录的 `examples/`。

## 场景 A —— AI 生成海报 → 云端打印 → 送达门口

**目标：** 演示最具代表性的 "AI 做出实物，并出现在我家门口" 流程。

**参与者：** 用户、经 MCP 接入的单一 AI 代理、对接云打印厂商的 AIMP 网关、快递 API。

**领域：** `manufacturing.print.2d.v1` + `logistics.shipping.v1`

**流程：**

1. 用户："给我做一张 A3 赛博朋克风海报，寄过来。预算 25 美元。"
2. 代理生成 300 dpi CMYK PNG，存于签名 URL。
3. `aimp.discover({"device_filter":{"domains":["manufacturing.print.2d.v1"]}})` →
   返回单个设备 `cloudprint-us-west`。
4. `aimp.quote`：
   ```json
   {
     "device_id": "cloudprint-us-west",
     "domain": "manufacturing.print.2d.v1",
     "asset": {"url": "...", "format": "image/png", "hash_sha256": "..."},
     "payload": {
       "paper_size": "A3",
       "paper_stock": "matte_200gsm",
       "dpi": 300,
       "color_mode": "CMYK",
       "copies": 1
     },
     "logistics": {
       "carrier_preference": "standard",
       "recipient": {"name":"...", "address_lines":["..."], "postal_code":"...", "country":"US"}
     },
     "budget_limit": {"amount": 25.00, "currency": "USD"}
   }
   ```
   网关返回 `quote_id`，`estimated_cost.amount = 18.20`。
5. 代理检查预算，调用 `aimp.execute({"quote_id": "..."})`。
6. 网关状态迁移 `LOCKED → EXECUTING → FULFILLING`，通过 Webhook 推送带有快递单号的
   发货事件。
7. 网关到达 `COMPLETED`。代理回复用户：
   "已打印并寄出。FedEx #7721... 周二送达。扣费 18.20 美元。"

关键观察：

- 代理内无任何适配器代码，一切经由五个 MCP 工具完成。
- 预算在网关侧强制，而非仅依赖代理的 "自觉"。
- 常规 2D 打印无需视觉审核——卡纸检测已足够。

## 场景 B —— 带中途人工审查的 3D 齿轮打印

**目标：** 展示一个 `restricted`（受限）风险等级的作业，
结合 AI 视觉检查与强制的人工检查点。

**参与者：** 设计代理、审核代理、执行代理（三者之间走 A2A），
AIMP 网关、本地 FDM 打印机、人工审查员。

**领域：** `manufacturing.additive.fdm.v1`

**流程：**

1. 设计代理根据用户提供的 CAD 生成 `gear.gcode`。
2. 审核代理校验几何结构后，向执行代理签字放行。
3. 执行代理 `aimp.quote`：
   ```json
   {
     "device_id": "printer-lab-01",
     "domain": "manufacturing.additive.fdm.v1",
     "asset": {"url": "...", "format": "model/gcode", "hash_sha256": "..."},
     "payload": {
       "material_requirement": "PETG",
       "parameters": {
         "nozzle_temp_celsius": 240,
         "bed_temp_celsius": 80,
         "infill_percent": 35,
         "layer_height_mm": 0.2
       }
     }
   }
   ```
4. 报价：2.30 美元，73 分钟。执行代理转交财务代理审批，取得 `approval_token`。
5. `aimp.execute`，附带 `audit_requirements`：
   ```json
   {
     "snapshot_interval_seconds": 300,
     "snapshot_channels": ["camera.top"],
     "sensors": ["extruder_temp", "chamber.temp"],
     "ai_vision_checks": ["detect_spaghetti_failure"],
     "pause_for_human_at": ["mid_build_50_percent"]
   }
   ```
6. 打印进度达 0.50 时 → 进入 `AUDITING`。网关向车间操作人的 Lark / Slack 发送
   `human_action_required`。
7. 操作人查看相机画面，确认层间附着正常，签字批准。执行代理调用 `/resume`，
   `decision: "CONTINUE"`。
8. 审核代理在每次快照时运行视觉检查；进度 0.72 时标记 `detect_spaghetti_failure`
   裁决为 `warn`，置信度 0.61。作业继续，但该遥测事件已被打上标记。
9. 进度 1.0 完成。最终扣费 2.28 美元。

关键观察：

- 三个代理协同工作，但仅执行代理触碰 AIMP。
- 自动（视觉）与人工审查均为一等状态。
- 若审查员看到拉丝迹象，`ADJUST` 恢复可将喷嘴温度提升 5 °C。

## 场景 C —— 实验室试剂板的移液操作

**目标：** 演示一个与打印无关的领域，以证明核心层的通用性。

**参与者：** 协议代理（生物学专用）、实验室中的 AIMP 网关、移液机器人、科学家审查员。

**领域：** `fluidics.pipette.v2`

**流程：**

1. 协议代理解读实验协议描述："从 1 号板 A 行取 15 µL，转移至 2 号板 B3 起始位置，
   慢速吸液。"
2. `aimp.discover` 返回 `pipette-rob-07`，
   其 `audit_channels: ["camera.workcell", "liquid_level"]`。
3. `aimp.quote` 负载：
   ```json
   {
     "device_id": "pipette-rob-07",
     "domain": "fluidics.pipette.v2",
     "payload": {
       "operations": [
         {"step": 1, "type": "ASPIRATE", "source_well": "Plate_1_A1",
          "volume_microliters": 15.0, "aspirate_speed_ul_per_sec": 5.0},
         {"step": 2, "type": "DISPENSE", "destination_well": "Plate_2_B3",
          "volume_microliters": 15.0, "dispense_speed_ul_per_sec": 10.0},
         {"step": 3, "type": "ASPIRATE", "source_well": "Plate_1_A2",
          "volume_microliters": 15.0, "aspirate_speed_ul_per_sec": 5.0},
         {"step": 4, "type": "DISPENSE", "destination_well": "Plate_2_B4",
          "volume_microliters": 15.0, "dispense_speed_ul_per_sec": 10.0}
       ]
     },
     "audit_requirements": {
       "sensors": ["liquid_level"],
       "ai_vision_checks": ["detect_bubble_formation"]
     }
   }
   ```
4. 报价：0.40 美元，2 分钟。执行。
5. 第 3 步时检测到气泡 → 裁决 `warn`，置信度 0.88。因策略对危险试剂上的 `warn`
   设为强制暂停，作业进入 `AUDITING`。
6. 科学家查看相机画面，签字批准继续。协议完成。

关键观察：

- 与场景 A、B 使用完全相同的核心动词与信封。
- 差异仅在 `domain` 与 `payload`。
- 审核策略在网关侧调优，不硬编码于代理。

## 场景 D —— 智慧厨房：低温慢煮牛排

**目标：** 一个消费级 / 危险等级的对照示例。

**参与者：** 家庭用户、嵌入家电内置 Hub 的厨房代理、家电内嵌的 AIMP 网关。

**领域：** `thermodynamics.cooking.v1`

**流程：**

1. 用户："把肋眼煎到三分熟。"
2. 代理查阅用户偏好；选择 55 °C 中心温、加热 1 小时 20 分钟，再 30 秒高温煎烤。
3. `aimp.quote` → 0.14 美元（能耗），1 小时 25 分钟。
4. 预算极小；策略不要求审批令牌。
5. `aimp.execute`，附：
   ```json
   "audit_requirements": {
     "sensors": ["water_bath_temp", "core_temp"],
     "ai_vision_checks": ["detect_char_on_food"]
   }
   ```
6. 作业运行。煎烤阶段，视觉检测到焦化程度超预期 → 裁决 `warn`。
   因该领域风险等级为 `restricted` 而非 `hazardous`，且置信度未达阈值，
   策略选择 `CONTINUE`。
7. 完成。代理告知用户："完成。中心温 54.8 °C，表面略深于目标——下次要调整吗？"

关键观察：

- 连台面家电也可原生支持 AIMP；只需在同一 SoC 上同时运行网关与适配器。
- 视觉检查产生的不仅是安全门控，还是下一次运行的学习信号。

## 互操作性小结

上述四个场景共享：

- 相同的五个核心动词（`discover`、`quote`、`execute`、`telemetry`、`abort`）；
- 相同的信封（§01.3）与状态机（§01.4）；
- 相同的鉴权、预算与审计日志范式。

它们仅在以下方面有差异：

- `domain` 字符串；
- `payload` 结构（由各领域 JSON Schema 约束）；
- 该领域下注册的传感器与 `ai_vision_checks` 集合。

这正是 AIMP 的要义：**物理世界是复数的，但与之交互的契约可以是单数的。**
