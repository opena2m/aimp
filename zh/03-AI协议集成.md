# AIMP 03 — AI 协议集成

**状态:** 草案 · **版本:** 1.0.0-draft · **信息性 & 规范性**

AIMP 的设计目标是搭载在既有 AI 工具标准之上。本章规定 AIMP 如何通过三种主流方式暴露给
AI：

- **模型上下文协议（MCP）** —— 首选绑定方式。
- **OpenAI 兼容函数调用** —— JSON Schema 工具直出。
- **Agent-to-Agent（A2A）拓扑** —— AIMP 在多 Agent 系统中的定位。

只要你的 Agent 能通过其中任意一种方式调用工具，它就能在不直接接触 HTTP 客户端的情况下，
驱动物理机器。

## 1. MCP 绑定（首选）

### 1.1 拓扑

```
┌───────────────┐   MCP (JSON-RPC 2.0)   ┌──────────────────────┐   AIMP/HTTPS   ┌──────────┐
│  MCP 客户端    │ ─────────────────────▶ │  AIMP MCP Server     │ ─────────────▶ │ 硬件适配器│
│  (LLM 宿主)   │                        │  (= AIMP 网关)       │                │           │
└───────────────┘                        └──────────────────────┘                └──────────┘
```

AIMP 网关 **应当** 向外暴露 MCP Server 接口。合规的 MCP 客户端因此无需写一行 AIMP 专属
代码即可发现并调用工具。网关负责把 MCP 的 `tools/call` 调用翻译为 §01 中等价的 AIMP
方法调用。

### 1.2 工具表面

网关 **至少必须** 暴露以下 MCP 工具：

| MCP 工具名 | AIMP 方法 | 备注 |
|---|---|---|
| `aimp.discover` | §01.6.1 `discover` | 返回设备列表与领域 |
| `aimp.quote` | §01.6.2 `quote` | 返回 `quote_id` 与成本明细 |
| `aimp.execute` | §01.6.3 `execute` | 需先有 `quote_id` |
| `aimp.telemetry` | §01.6.4 `telemetry` | 返回状态、进度、媒体 URL |
| `aimp.abort` | §01.6.5 `abort` | 永不限流 |

对于低风险的常规操作，网关 **可以** 额外暴露一些特定领域的便捷工具，例如
`aimp.manufacturing.print.2d.quick_print`，将 quote + execute 打包成一次调用，并内置
明确的预算上限。便捷工具在内部 **仍然必须** 遵守"询价-锁定-执行"的生命周期。

### 1.3 `tools/list` 响应示例

```json
{
  "tools": [
    {
      "name": "aimp.quote",
      "description": "为一项物理任务获取正式报价。不会启动任何物理动作。",
      "inputSchema": {
        "type": "object",
        "required": ["device_id", "domain", "payload"],
        "properties": {
          "device_id": {"type": "string"},
          "domain":    {"type": "string", "pattern": "^[a-z]+(\\.[a-z0-9_]+)+\\.v[0-9]+$"},
          "asset":     { "$ref": "https://aimp.dev/schemas/core/asset.json" },
          "payload":   { "description": "按 `domain` 对应的 Schema 进行校验" },
          "logistics": { "$ref": "https://aimp.dev/schemas/core/logistics.json" },
          "budget_limit": {
            "type": "object",
            "properties": {
              "amount":   {"type": "number"},
              "currency": {"type": "string", "pattern": "^[A-Z]{3}$"}
            }
          }
        }
      }
    },
    {
      "name": "aimp.execute",
      "description": "提交先前的报价并启动物理执行。除中止外不可逆。",
      "inputSchema": { "$ref": "https://aimp.dev/schemas/core/execute-request.json" }
    }
  ]
}
```

### 1.4 Resources 与 Prompts

MCP 的 Resources 与 Prompts **也可以** 配合使用：

- **Resources:** AIMP 网关 **应当** 把每台设备的当前状态和近期遥测以 MCP Resource 形式
  发布，URI 形如 `aimp://device/printer-01/state`。
- **Prompts:** 网关 **可以** 发布起步 prompt，引导大模型用安全的"先询价再执行"流程调用
  常见领域。

## 2. 函数调用绑定

对于直接使用 OpenAI / Anthropic / Gemini 函数调用（不走 MCP）的 Agent，网关在以下地址
发布 JSON Schema 工具定义：

```
GET /v1/tools.json
```

返回结果是一个工具对象数组，可直接装载到任何兼容的函数调用运行时。内容与 MCP 的
`tools/list` 等价，只是以厂商中立的 JSON Schema 形式呈现。

## 3. Agent-to-Agent（A2A）拓扑

在多 Agent 系统中，AIMP 只扮演一个角色：**物理执行接口**。其他所有协作在 Agent 之间
完成。

### 3.1 推荐角色划分

| Agent | 职责 | 是否访问 AIMP？ |
|---|---|---|
| **设计 Agent** | 把自然语言意图转为 CAD、图像、G-code、配方。 | 否 |
| **审查 Agent** | 对设计进行物理、安全、法规合规检查。 | 否 |
| **财务 Agent** | 持有账本，签发 `approval_token`。 | 否 |
| **执行 Agent** | 与 AIMP 网关对话。**唯一** 的 AIMP 调用方。 | **是** |
| **审计 Agent** | 订阅遥测，运行视觉检查，建议继续/中止。 | 只读 |

将 AIMP 访问权限集中在"执行 Agent"一身上，有三大好处：

1. **可审计。** 所有物理调用都汇聚到一个身份可识别的主体。
2. **爆炸半径可控。** 即便设计 Agent 被提示词注入，也接触不到机器。
3. **一致性。** 速率限制和预算都针对一个已知调用方生效。

### 3.2 典型消息流

```
用户         ──"打印赛博朋克海报并寄给我"──▶ 设计 Agent
设计 Agent   ──生成 PNG + 元数据──▶ 审查 Agent
审查 Agent   ──通过──▶ 执行 Agent
执行 Agent   ──aimp.quote──▶ AIMP 网关             → 报价：18.20 USD
执行 Agent   ──报价──▶ 财务 Agent
财务 Agent   ──approval_token──▶ 执行 Agent
执行 Agent   ──aimp.execute(approval_token)──▶ AIMP 网关
AIMP 网关    ──状态变更──▶ 审计 Agent（已订阅遥测）
审计 Agent   ──进度 50% 视觉检查──▶ 执行 Agent（继续 / 中止）
AIMP 网关    ──COMPLETED + 运单号──▶ 执行 Agent
执行 Agent   ──自然语言回复──▶ 用户
```

### 3.3 跨协议契约

Agent 间消息不在 AIMP 范围内。但"财务 Agent → 执行 Agent → 网关"路径上传递的
`approval_token` 是规范性字段：

```json
{
  "approval_token": {
    "iss": "agent://org/finance-agent",
    "sub": "quote_01J8...",
    "iat": 1714000000,
    "exp": 1714003600,
    "max_amount": {"amount": 25.00, "currency": "USD"},
    "signature": "ed25519:..."
  }
}
```

网关 **必须** 根据预配置的信任根校验签名；对 `sub` 与被执行 `quote_id` 不一致的
Token **必须** 拒绝。

## 4. 完整工作示例：从提示词到门口的海报

使用 MCP + AIMP 的端到端流程，附注释：

1. 用户："帮我做一张 A3 赛博朋克海报，寄到家里，预算 25 美元。"
2. LLM 生成 PNG，上传到对象存储。
3. LLM 调用 `aimp.discover({"device_filter":{"domains":["manufacturing.print.2d.v1"]}})`，
   网关返回一台云打印设备。
4. LLM 调用 `aimp.quote`，传 PNG URL 与 `payload = {paper_size: "A3", dpi: 300,
   color_mode: "CMYK"}`。网关返回 `quote_id` 与 `estimated_cost.amount = 18.20`。
5. LLM 判断 `18.20 ≤ 25.00`，决定继续，调用 `aimp.execute(quote_id)`。
6. 网关 `LOCKED → EXECUTING`。LLM 每 60 秒轮询 `aimp.telemetry`。
7. 进入 `FULFILLING`，网关返回运单号。
8. 到达 `COMPLETED`，LLM 以自然语言回复用户，附成本、运单号、预计到达时间。

整个过程 LLM 没有接触过 HTTP、JSON-RPC、MQTT。它只接触了五个工具。

## 5. 绑定层的安全

- MCP 的传输 **必须** 端到端认证（stdio + 签名，或 HTTPS + Token）。
- `tools/list` 中的工具描述 **不得** 泄露秘密；网关应按调用者返回脱敏后的 Schema。
- 工具结果 **不得** 包含高分辨率原始素材。使用预签名 URL（§01.6.4）。
- Agent **应当** 将 `aimp.telemetry` 中的媒体视为 **不受信任内容**：被入侵的适配器
  可能在摄像头画面中渲染文字做提示词注入。用于审核的视觉模型 **应当** 沙箱化运行，禁止
  访问任何工具。

## 6. 本绑定的非目标

- AIMP 不规定多 Agent 系统中谁担任执行 Agent；请交由 A2A 框架的角色分配机制。
- AIMP 不提供 Agent 框架本身。LangGraph、AutoGen、CrewAI、DSPy 等任选；AIMP 只是它们
  调用的工具集。
