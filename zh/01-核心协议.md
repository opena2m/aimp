# AIMP 01 — 核心协议

**状态:** 草案 · **版本:** 1.0.0-draft · **规范性**

本文档定义 AIMP 的 **领域无关内核**。任何合规的 AIMP 网关 **必须** 实现本章列出的全部
方法。领域特定行为见 §02。

## 1. 传输与编码

- 请求与响应 **必须** 使用 UTF-8 编码的 JSON（RFC 8259）。
- **推荐** 的传输方式是 HTTPS，配合 REST 语义与 JSON Body。
- 长时间遥测 **可以** 额外通过 WebSocket、MQTT 或 SSE 提供；但网关仍 **必须** 暴露 §6.4
  定义的轮询接口。
- 所有时间戳 **必须** 为 RFC 3339 格式，并带显式时区偏移（优先使用 UTC）。
- 所有时长 **必须** 使用整数秒数，除非 Schema 明确另行规定。
- 所有货币金额 **必须** 附带 ISO 4217 货币代码。

## 2. 协议角色

| 角色 | 说明 |
|---|---|
| **客户端（Client）** | 发起 AIMP 调用的 AI Agent（直接调用或通过 MCP）。 |
| **网关（Gateway）** | AIMP 服务端。持有策略、预算、账本、任务注册表、适配器路由。 |
| **适配器（Adapter）** | 面向物理设备的边缘组件。对客户端透明。 |

本文中对 AIMP 接口的所有规范性描述，其实施主体均为 **网关**。

## 3. 通用请求信封

每一个 AIMP 请求 Body **必须** 包装在如下通用信封中：

```json
{
  "aimp_version": "1.0",
  "job_id": "01J8K9Z4X0R3S7Q6V2N4T8W1YM",
  "timestamp": "2026-04-24T05:19:36Z",
  "idempotency_key": "客户端生成的不透明字符串",
  "metadata": {
    "creator": "agent://acme-factory/design-bot-7",
    "trace_id": "opentelemetry-trace-id",
    "tags": {"project": "poster-run-17"}
  }
}
```

除信封字段外，每个方法再定义自己的 Body 字段。

- `aimp_version` —— **必须** 与网关实现的 major.minor 一致。
- `job_id` —— 由 **客户端** 生成的 ULID 或 UUIDv7，作为网关级别的可见标识符。
- `idempotency_key` —— **可选但推荐**。在保留期内网关收到相同 `idempotency_key` 的重复
  请求时，**必须** 返回原始响应，而 **不得** 再次执行。
- `metadata` —— 自由字段；若其中包含 `trace_id`，网关 **必须** 在遥测和 webhook 中回显。

## 4. 核心状态机

每个任务（`job_id`）按顺序流转下列状态的一个子集。状态 **不得** 跳跃，但随时转换到
`ABORTED` 或 `FAILED` 永远合法。

```
   PENDING
       │
       ▼
   QUOTED ─────────────────────┐
       │                       │
       ▼                       │
   LOCKED                      │
       │                       │
       ▼                       │
   EXECUTING ◀──┐              │
       │        │              │
       ▼        │              │
   AUDITING ────┘   （恢复）    │
       │                       │
       ▼                       │
   FULFILLING                  │
       │                       ▼
       │                  ABORTED / FAILED
       ▼
   COMPLETED
```

| 状态 | 含义 | 是否终态？ |
|---|---|---|
| `PENDING` | 网关接收到信封；校验进行中。 | 否 |
| `QUOTED` | 已签发带有价格和 `valid_until` 的有效报价。 | 否 |
| `LOCKED` | 客户端已确认，资源已保留，物理工作尚未开始。 | 否 |
| `EXECUTING` | 机器正在执行物理动作。`progress` 字段有意义。 | 否 |
| `AUDITING` | 执行暂停，等待 AI 或人工审核。 | 否 |
| `FULFILLING` | 执行完成，正在进行物流（打包、发货）。 | 否 |
| `COMPLETED` | 成功终态。 | **是** |
| `ABORTED` | 终态 —— 客户端或策略中止任务。**可能** 产生部分费用。 | **是** |
| `FAILED` | 终态 —— 物理过程或适配器失败。**必须** 附带 `error_code`。 | **是** |

网关 **必须** 拒绝不在状态表中的客户端发起的状态变更。仅有 `ABORT`（§6.5）和 从
`AUDITING` 恢复是客户端发起的，其他均由网关驱动。

## 5. 身份、鉴权与信任

- 客户端 **必须** 在每一次请求中完成认证。**推荐** 使用 OAuth 2.1 短期 Bearer Token，
  并按设备或领域进行 Scope 划分。
- 网关 **必须** 为每个 Token 维护一份 **策略**，限定：（a）允许的 `domain`；（b）允许
  的设备；（c）预算上限。
- Human-in-the-Loop 审批（§04）**必须** 由与 Agent 不同的主体签发。
- 网关 **必须** 将每一次状态变更和策略决策写入追加式审计日志。

## 6. 核心方法

核心协议仅定义 **五个** 动词。其他任何接口都属于领域扩展（§02）或网关便捷方法。

### 6.1 `discover` —— 能力握手

**目的:** 让客户端在任何承诺性调用之前，先了解网关的能力。

```
POST /v1/discover
Content-Type: application/json
Authorization: Bearer <token>

请求体:
{
  "envelope": { ...通用信封... },
  "device_filter": {
    "domains": ["manufacturing.additive.*"],
    "device_ids": ["printer-01"]
  }
}
```

**响应:**

```json
{
  "job_id": "<与请求一致>",
  "aimp_version": "1.0",
  "conformance_level": "L3",
  "devices": [
    {
      "device_id": "printer-01",
      "device_class": "PRINTER_3D",
      "domains": ["manufacturing.additive.fdm.v1"],
      "state": "IDLE",
      "consumables": [
        {"name": "PLA_white", "quantity": 412.5, "unit": "g"},
        {"name": "PETG_black", "quantity": 0.0, "unit": "g"}
      ],
      "build_volume_mm": {"x": 220, "y": 220, "z": 250},
      "audit_channels": ["camera.top", "sensor.extruder_temp"]
    }
  ]
}
```

网关 **应当** 对 `discover` 响应做短时缓存（秒级，而非分钟级）；耗材数量变化很快。

### 6.2 `quote` —— 为拟议任务定价

**目的:** 获取一份有时效的正式报价。**不得** 启动任何物理动作。

```
POST /v1/quote

请求体:
{
  "envelope": { ...通用信封... },
  "device_id": "printer-01",
  "domain": "manufacturing.additive.fdm.v1",
  "asset": {
    "type": "3D_MODEL",
    "format": "model/gcode",
    "url": "https://assets.example.com/gear.gcode",
    "hash_sha256": "e3b0c44..."
  },
  "payload": { ...领域特定参数... },
  "logistics": { ...可选收件信息... },
  "budget_limit": {"amount": 25.00, "currency": "USD"}
}
```

**响应:**

```json
{
  "job_id": "<与请求一致>",
  "state": "QUOTED",
  "quote_id": "quote_01J8...",
  "estimated_cost": {
    "currency": "USD",
    "amount": 18.20,
    "breakdown": {
      "material": 6.40,
      "machine_time": 4.80,
      "logistics": 7.00,
      "service_fee": 0.00
    }
  },
  "resource_consumption": {
    "material": [{"name": "PLA_white", "quantity": 38.2, "unit": "g"}],
    "machine_time_seconds": 4380,
    "energy_kwh": 0.42
  },
  "valid_until": "2026-04-24T06:19:36Z"
}
```

若报价金额超过 `budget_limit`，网关 **仍必须** 返回 `QUOTED` 响应，并额外置
`exceeds_budget: true`。由客户端决定是否放弃。

### 6.3 `execute` —— 确认报价并启动任务

**目的:** 承诺报价，锁定资源，开始物理执行。

```
POST /v1/execute

请求体:
{
  "envelope": { ...通用信封... },
  "quote_id": "quote_01J8...",
  "approval_token": "<若策略要求人工批准则必填>",
  "audit_requirements": {
    "snapshot_interval_seconds": 180,
    "sensors": ["extruder_temp", "chamber_temp"],
    "ai_vision_checks": ["detect_spaghetti_failure"],
    "pause_for_human_at": ["mid_build_50_percent"]
  }
}
```

**立即响应（通常为 `202 Accepted`）:**

```json
{
  "job_id": "<与请求一致>",
  "state": "LOCKED",
  "transition_eta": "2026-04-24T05:19:40Z"
}
```

随后网关 **必须** 异步推进状态机（§4），并通过 webhook、流或轮询推送更新。

客户端 **不得** 在 `state == "EXECUTING"` 之前假定任何物理动作已发生。

### 6.4 `telemetry` —— 观测

**目的:** 查询当前状态与多模态审核数据。

```
GET /v1/jobs/{job_id}/telemetry
GET /v1/jobs/{job_id}/telemetry?since=<rfc3339>
```

**响应:**

```json
{
  "job_id": "01J8K9...",
  "state": "EXECUTING",
  "progress": 0.47,
  "updated_at": "2026-04-24T05:41:02Z",
  "sensor_readings": [
    {"channel": "extruder_temp", "value": 210.2, "unit": "degC", "at": "2026-04-24T05:41:00Z"},
    {"channel": "chamber_temp",  "value": 41.1,  "unit": "degC", "at": "2026-04-24T05:41:00Z"}
  ],
  "media": [
    {
      "channel": "camera.top",
      "kind": "image/jpeg",
      "url": "https://gateway.example.com/media/job-01J8.../top-00012.jpg",
      "captured_at": "2026-04-24T05:40:59Z",
      "expires_at": "2026-04-25T05:40:59Z"
    }
  ],
  "human_action_required": null
}
```

Media URL **必须** 为预签名的短时链接。客户端 **不得** 在 `expires_at` 之后继续使用。

若状态为 `AUDITING`，响应 **必须** 包含 `human_action_required` 字段，携带恢复任务所需的
信息（详见 `05-审核与遥测.md`）。

### 6.5 `abort` —— 立即停止

**目的:** 物理急停。最高优先级。

```
POST /v1/jobs/{job_id}/abort

请求体:
{
  "envelope": { ...通用信封... },
  "reason": "vision_check_failed_spaghetti",
  "recovery_mode": "safe_home"
}
```

**响应:**

```json
{
  "job_id": "01J8K9...",
  "state": "ABORTED",
  "final_cost": {"currency": "USD", "amount": 2.85, "breakdown": {...}},
  "partial_outputs": [
    {"kind": "scrap", "description": "失败打印件，约 12 g PLA", "disposal": "user-collect"}
  ]
}
```

适配器 **必须** 以尽可能短的延迟执行中止。`hard_stop` 立即切断电机与加热；`safe_home` 将
刀具/工具归位安全位置；`freeze` 保持现状等待人工检查。网关 **必须** 校验设备是否支持所请求
的模式；若不支持，**必须** 回退到最保守的可用模式，并在响应中说明。

## 7. Webhook 通知

提供 webhook 投递的网关，对每个订阅的任务、每一次状态变更 **必须** 推送如下 JSON：

```json
{
  "event": "state_transition",
  "aimp_version": "1.0",
  "job_id": "01J8K9...",
  "from": "EXECUTING",
  "to":   "AUDITING",
  "at":   "2026-04-24T05:49:18Z",
  "telemetry_summary": { ...§6.4 响应的子集... },
  "signature": "hmac-sha256=..."
}
```

Webhook **必须** 使用每订阅独立密钥，对规范化 Body 做 HMAC-SHA256 签名。接收端
**必须** 拒绝未签名或签名错误的 webhook。重试 **应当** 采用指数退避，最长不超过 24 小时。

## 8. 幂等性

- 对 `quote` 或 `execute` 用相同 `idempotency_key` 重复 POST 时，在保留期内
  （**推荐** 24 小时）**必须** 返回原始结果，而 **不得** 重新执行。
- `abort` 天然幂等；对终态任务重复中止 **必须** 静默成功。
- `discover` 与 `telemetry` 天然幂等。

## 9. 速率限制

网关 **必须** 通过 `X-RateLimit-*` HTTP 头向客户端暴露每 Token 的速率限制。客户端
**必须** 遵守 `Retry-After`。**推荐** 的默认值：

| 方法 | 每分钟 | 每小时 |
|---|---|---|
| `discover`、`telemetry` | 120 | 3000 |
| `quote` | 30 | 300 |
| `execute` | 10 | 120 |
| `abort` | 不限 | 不限 |

`abort` 永不限流：物理安全永远优先。

## 10. 最小合规测试

实现若要宣告达到 **L1 核心** 合规，必须使用参考桩设备满足：

1. `/discover` 返回至少一个设备条目。
2. `/quote` 返回 `QUOTED` 状态，附 `quote_id` 与未来 ≥ 30 秒的 `valid_until`。
3. 对应的 `/execute` 在 500 ms 内返回 `LOCKED`。
4. 通过 `/telemetry` 轮询，在合理时间内到达 `COMPLETED`。
5. 在任何非终态状态下，`/abort` 可正常工作。

参考测试向量发布在 `schemas/` 及配套合规测试套件中。
